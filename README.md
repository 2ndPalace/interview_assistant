# 面接アシスタント

オンライン面接の **練習** と **本番** を手伝う Windows 用のアプリです。

- **練習モード**：アプリが面接の質問を読み上げます。あなたがマイクに向かって答えると、言えたこと・言い忘れたこと・話した時間・「えーと」などの口癖を教えてくれます。
- **本番モード**：Zoom・Teams・Google Meet などで面接官が話した質問を聞き取り、答えるときの要点を画面に大きく表示します。

面接を受ける会社ごとに質問のセット（「プロファイル」と呼びます）を切り替えて使えます。

もっと詳しい手順や、うまく動かないときの対処は [使い方ガイド（GUIDE.md）](GUIDE.md) を見てください。

# はじめての方へ

## 用意するもの

- Windows 10 または 11 のパソコン
- Python（3.10 以上）… アプリを動かすためのソフトです。[python.org](https://www.python.org/downloads/) から入れられます。入れるときは、最初の画面の「Add python.exe to PATH」に必ずチェックを入れてください。
- Git … アプリをダウンロードするためのソフトです。[git-scm.com](https://git-scm.com/) から入れられます。
- マイク（練習モードで使います）
- インターネット接続（最初の1回だけ、音声認識のデータを自動でダウンロードします）

## インストール（最初の1回だけ）

1. スタートボタンを右クリックし、「ターミナル」または「Windows PowerShell」を開きます。
2. 次の文字を1行ずつコピーして貼り付け、Enter キーを押します。

   ```powershell
   git clone https://github.com/2ndPalace/interview_assistant.git
   cd interview_assistant
   python -m venv .venv
   .\.venv\Scripts\Activate.ps1
   pip install -r requirements.txt
   ```

   1行目でアプリをダウンロードし、2行目でそのフォルダに移動します。3行目と4行目は、このアプリ専用の作業場所を作って、そこに入る操作です。5行目で必要な部品が入ります（数分かかります）。

3. 4行目で「スクリプトの実行が無効」という赤い文字が出たときは、次を1回だけ実行してから、もう一度4行目を実行してください。

   ```powershell
   Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
   ```

## 起動のしかた

PowerShell を開いて、次の3行を実行します。

```powershell
cd interview_assistant
.\.venv\Scripts\Activate.ps1
python interview_assistant.py
```

初めて起動したときは、音声認識のデータのダウンロードに数分かかります。画面のいちばん下に「準備完了」と出たら使えます。

ダウンロードした直後は、面接先のデータが入っていません。起動時に「profiles フォルダに面接先のファイルがありません」と出たら、先に下の「面接先を追加する」の手順で面接先を作ってください。

## 練習モードの使い方

1. 「次の質問（苦手優先）」を押すと、質問が読み上げられます。まだ練習していない質問や、うまく答えられなかった質問が優先して出ます。
2. 「回答開始」を押して、声に出して答えます。5 秒だまるか、「回答終了」を押すと終わります。考えながらゆっくり話しても途中で切れません。
3. 結果が表示されます。
   - 緑の ○ … 言えた要点
   - 赤の × … 言い忘れた要点
   - 紫 … まだ自分で書いていない項目（下の「面接先を追加する」を参照）
   - 話した時間、口癖の回数も出ます
4. 「模範回答を見る」で、答えのお手本を全部読めます。

## 本番モードの使い方

1. 画面上の「本番」を選び、「カメラ下に配置」を押します。アプリが画面の上のほう（カメラのすぐ下）に移動し、いつも手前に表示されます。
2. 「聞き取り開始」を押します。面接官が質問すると、答えの要点が大きく表示されます。
3. 練習で言い忘れたことのある要点は、オレンジ色で表示されます。
4. 違う質問が表示されたときは、下の候補ボタンか、キーボードの F1・F2・F3 で切り替えられます。Esc キーで表示を消せます。
5. 聞き取れなかったときは、「手入力」の欄に質問を打って Enter を押します。

## 面接先を追加する

1. PowerShell で次を実行します（「sample」と「サンプル商事（インターン）」は、面接先に合わせて変えてください）。

   ```powershell
   python new_profile.py sample "サンプル商事（インターン）" --type intern
   ```

   最後の `--type` は、アルバイトなら `baito`、新卒採用なら `shinsotsu`、インターンなら `intern` にします。よく聞かれる質問が最初から入ります。

2. `profiles` フォルダにできた `sample.json` を、メモ帳などで開きます。`[要記入]` と書かれているところを、自分の言葉に書き換えて保存します。
   - 特に「志望動機」と「会社について知っていること」は、会社ごとに必ず書いてください。
   - `vocabulary` の欄に会社名・サービス名などを書いておくと、聞き取りの精度が上がります。
3. アプリの上にある「面接先」から選びます。次に起動したときも、最後に選んだ面接先のままになります。

自己紹介・長所・短所など、どの会社でも聞かれる質問は `profiles/_common.json` にまとめて入っています。初めて起動したときに、ひな形の `profiles/_common.example.json` からコピーして作られるので、`[要記入]` を自分の言葉で埋めてください。ここを1回直せば、すべての面接先に反映されます。

`_common.json` と会社ごとのファイル（`sample.json` など）は、あなたのパソコンの中にだけ保存され、GitHub には上がりません。説明会や選考で知った情報は外に出さないよう求められることが多いためです。

## 本番の前に必ず確認すること

- **事前に一度テストする**：会議アプリで面接の動画などを流し、本番モードで聞き取れるか試してください。画面の音量バーが動かないときは、Windows の音の出力先と、会議アプリの音の出力先がずれています。
- **画面共有をするときは、このアプリを最小化する**：そのままだと面接官にも見えてしまいます。
- **ファイルを書き換えたら「UTF-8」のまま保存する**：カンマを消してしまうなど書き方を間違えると、面接先の名前の横に「JSONエラー」と表示されます。

# しくみと基礎知識

このアプリがどうやって「聞いて」「文字にして」「どの質問か当てて」いるのかを、専門知識がなくても読めるように説明します。

## 全体の流れ

```
面接官の声（スピーカーの音）
   │  ① 録音する ……………… 音を取り込み、話している部分だけを切り出す
   ▼
話している部分の音声
   │  ② 文字にする ………… 音声認識 AI（Whisper）が文章にする
   ▼
「志望動機を教えてください」
   │  ③ どの質問か当てる … 用意した質問リストと似ているものを探す
   ▼
「志望動機」の要点を画面に表示
```

## このアプリを支える技術

| 技術 | どこで使っているか | ひとことで言うと |
|---|---|---|
| **Whisper**（OpenAI） | ② 文字にする | 大量の音声で学習した音声認識 AI。日本語も高い精度で文字にできる |
| **whisper.cpp** | ② 文字にする（GPU 版） | Whisper を C/C++ で軽く速く動かせるようにしたもの。今回は AMD の GPU で動かすために使用 |
| **Vulkan** | ② 文字にする（GPU 版） | ゲームでも使われる、GPU に計算させるための共通の仕組み。メーカーを問わず使える |
| **faster-whisper** | ② 文字にする（予備） | Whisper を速く動かす別の方法。GPU 版が使えないときに CPU で動く |
| **Silero VAD** | ② 文字にする | 「人の声かどうか」だけを判定する小さな AI。声のない部分を文字起こしから外す |
| **WASAPI ループバック**（soundcard） | ① 録音する | Windows がスピーカーに送っている音を、そのまま横から受け取る仕組み |
| **TF-IDF と文字 n-gram**（scikit-learn） | ③ どの質問か当てる | 文章同士がどれくらい似ているかを数字で測る方法 |
| **音声合成**（Windows SAPI5） | 練習モード | 質問を読み上げるパソコンの声 |
| **Tkinter** | 画面 | Python に付いてくる、ウィンドウやボタンを作る道具 |

## 知っておくと役に立つ基礎知識

### 音のデジタル化（サンプリング周波数）

パソコンの中の音は、1 秒間に何万回も音の大きさを測った数字の列です。1 秒に測る回数を **サンプリング周波数** と呼びます。Windows の音は普通 1 秒に 48,000 回（48kHz）ですが、Whisper は 16,000 回（16kHz）の音を前提にしているので、アプリの中で変換しています。人の声を聞き取るには 16kHz で十分です。

### 音量（RMS）と「話しているかどうか」の判定

アプリは 0.1 秒ごとに音の大きさ（**RMS**：波の大きさの平均のようなもの）を測り、ある基準（**閾値**）より大きければ「話している」と判断します。

ここで難しいのが基準の決め方です。基準が高すぎると小さな声を聞き逃し、低すぎると雑音まで拾います。このアプリは「直近 5 秒の中で静かだった時間の音量」を雑音の大きさとみなし、その 2 倍を基準にしています。周りの騒がしさに合わせて基準が自動で動くので、BGM がある場合でも声を拾えます。

### VAD（音声区間検出）

**VAD**（Voice Activity Detection）は、音の中から「人の声がしている部分」を見つける技術です。音量だけで判断する方法（上の RMS）は簡単ですが、物音や音楽も「音がある」と判断してしまいます。Silero VAD のような AI を使う方法は、声の特徴そのものを見て判断するので、より正確です。このアプリは、まず音量で大まかに切り出し、文字にする段階で Silero VAD がさらに声だけを選びます。

### 音声認識 AI の「幻聴」（ハルシネーション）

Whisper は動画の字幕などで学習しているため、声が入っていない音を渡されると「ご視聴ありがとうございました」のような、動画の最後によくある言葉を作り出すことがあります。これを **ハルシネーション** と呼びます。このアプリでは、結果がそうした決まり文句だけのときは捨てるようにしています。

### 文字の選び方（貪欲法とビームサーチ）

Whisper は文章を 1 文字（正確には 1 トークン）ずつ、「次に来そうな文字」を予想しながら作ります。

- **貪欲法（greedy）**：毎回いちばん可能性の高いものを選ぶ。速い。
- **ビームサーチ**：候補を何通りか同時に持ちながら進め、最後に一番良いものを選ぶ。少し正確になることがあるが遅い。

このアプリは、GPU 版で複数の候補を同時に扱うと異常終了する問題があったため、貪欲法を使っています。

### ヒント語（initial_prompt）

Whisper には、文字起こしの前に「この音声にはこういう言葉が出てきます」というヒントを渡せます。会社名や専門用語をプロファイルの `vocabulary` に書いておくと、それが聞き取りやすくなるのはこのためです。

### CPU と GPU

**CPU** はパソコンの頭脳で、どんな仕事もこなせますが、同時にこなせる計算の数は多くありません。**GPU** は画面を描くための部品で、単純な計算を数千個同時にこなすのが得意です。音声認識 AI の計算は「単純な計算の大量のくり返し」なので、GPU を使うと何倍も速くなります。このアプリでは、同じ音声を CPU で 2.6 秒、GPU で約 0.3 秒で文字にできました。

### どの質問かを当てるしくみ（文字 n-gram と TF-IDF）

聞き取った文章と、プロファイルに書いた質問の言い方（`variants`）を比べて、一番似ているものを選びます。

1. **文字 n-gram**：文章を 1〜3 文字ずつのかたまりに分けます。例：「志望動機」→「志」「望」「動」「機」「志望」「望動」「動機」「志望動」「望動機」。日本語は単語の区切りがないので、文字のかたまりで比べると扱いやすくなります。
2. **TF-IDF**：かたまりごとに重みを付けます。どの質問にも出てくる「ください」のような言葉は軽く、特定の質問にしか出てこない「志望」のような言葉は重くします。
3. **コサイン類似度**：重みを付けた 2 つの文章が、どれくらい同じ方向を向いているかを 0〜1 の数字で測ります。1 に近いほど似ています。

この数字が `MATCH_THRESHOLD`（0.35）未満なら「該当なし」と表示します。文字の並びで比べているので、「短所」と「欠点」のように意味が同じでも字が違う言葉は似ていると判断できません。そのため、よくある言い換えはアプリの中で同じ言葉にそろえています（欠点・弱み → 短所 など）。

### 精度の測り方（CER）

**CER**（Character Error Rate：文字誤り率）は、文字起こしの結果を正しい文章に直すのに、何文字の「置き換え」「削除」「追加」が必要かを、正しい文章の文字数で割ったものです。0% なら完全に一致、10% なら 100 文字あたり 10 文字ほど間違いがある、という意味です。

# 上級者向け

## フォルダ構成

```
interview_assistant.py   アプリ本体（Tkinter）
new_profile.py           プロファイルのひな形生成
profiles/
  _common.example.json   共通の質問のひな形（初回起動時に _common.json にコピーされる）
  _common.json           全面接先で共通の質問。自分の回答を含むため Git 管理外
  <id>.json              面接先固有の質問（共通と同じ id があれば上書き）。選考で知った情報を含むため Git 管理外
models/                  whisper.cpp 用モデル（Git 管理外）
practice_log.csv         練習記録（自動生成、Git 管理外）
```

## 処理の流れ

1. **録音**：`soundcard` で 48kHz 録音し、16kHz モノラルに変換。0.1 秒ごとの音量（RMS）が「直近 5 秒の音量の下位 20% × 2」を超えたら発話とみなして区間を切り出す。本番はスピーカー出力のループバック、練習は既定のマイク。
   - 以前は「発話していない間の平均音量 × 3」を閾値にしていたが、BGM のある音声では閾値が上がり続けて声を拾えなくなっていた（動画で区間に入ったのは全体の 31%）。
   - マイクは2チャンネルを平均せず、音の大きいチャンネルを使う（AG06 などはマイクが片方のチャンネルにだけ入り、平均すると声が半分の大きさになる）。練習の回答は文字起こしの前に音量をそろえる（`normalize_level`）。
   - ループバックデバイスは `default_speaker().id` で指定する。名前で探すと、出力と同名の入力を持つオーディオインターフェース（Yamaha AG06 など）で入力側が選ばれ、無音になる。
2. **文字起こし**（バックエンドを2段で選択）
   - `models/ggml-large-v3-turbo.bin` があり、Vulkan 版 `pywhispercpp` を import できれば **whisper.cpp（GPU）**。`models/ggml-silero-v5.1.2.bin` があれば Silero VAD を有効化。
   - どちらかが無ければ **faster-whisper**（CUDA float16 → 失敗したら CPU int8、`small`）。
   - どちらも、結果が「ご視聴ありがとうございました」などの決まり文句だけなら捨てる。
3. **質問判定**：正規化（御社→当社、句読点除去、同義語の統一、丁寧表現の除去）したうえで、文字 1〜3-gram の TF-IDF コサイン類似度 ＋ `keywords` 加点。`MATCH_THRESHOLD` 未満は「該当なし」。
4. **採点**（練習）：要点ごとの `check` 語が文字起こしに含まれるかで判定。共通の質問の記録は全面接先で、固有の質問の記録はその面接先だけで使う。

## 調整できる設定（`interview_assistant.py` の上部）

| 項目 | 既定値 | 内容 |
|---|---|---|
| `WHISPER_CPP_MODEL` | `models/ggml-large-v3-turbo.bin` | whisper.cpp（GPU）用のモデル。このファイルがあれば優先して使う |
| `WHISPER_CPP_VAD_MODEL` | `models/ggml-silero-v5.1.2.bin` | 声のない区間を文字起こししないための VAD モデル（任意） |
| `WHISPER_MODEL` | `small` | faster-whisper（CPU）用。精度不足なら `medium`（遅くなる） |
| `LIVE_SILENCE_END` | 0.8 秒 | 面接官が話し終えたと判断するまでの無音時間 |
| `PRACTICE_SILENCE_END` | 5.0 秒 | 練習で回答が終わったと判断するまでの無音時間 |
| `MIC_MIN_THRESHOLD` | 0.003 | 練習でマイクの音を声とみなす音量の下限。小さい声が拾われないなら下げる |
| `MIC_MAX_GAIN` | 20 | 練習で、文字起こしの前に小さい声を何倍まで大きくするか |
| `NOISE_WINDOW_SEC` / `NOISE_PERCENTILE` / `NOISE_MULT` | 5.0 秒 / 20 / 2.0 | 発話とみなす音量の決め方（直近 5 秒の下位 20% の 2 倍）。声を拾い損ねるなら `NOISE_MULT` を下げる |
| `MATCH_THRESHOLD` | 0.35 | これ未満は「該当なし」と表示 |

## 質問データの形式

```json
{
  "id": "motivation",
  "title": "志望動機",
  "variants": ["志望動機を教えてください", "なぜ当社を選んだのですか"],
  "keywords": ["志望", "選んだ"],
  "points": [{"text": "本番で表示する要点", "check": ["練習で言えたとみなす語"]}],
  "full": "模範回答の全文",
  "target_seconds": 50
}
```

- `variants`：面接官が言いそうな言い方。多いほど判定が当たりやすい
- `keywords`：その質問に特有の語（判定の加点に使う）
- `check` が空の要点は自動採点しない
- プロファイルの `vocabulary` は文字起こしの `initial_prompt` に渡される（`[要` で始まる未記入のひな形は除外）

## GPU（AMD 含む）で動かす

配布されている `pywhispercpp` は CPU 専用なので、Vulkan 対応で自分でビルドする。

1. モデルを `models/` に置く
   - https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-large-v3-turbo.bin
   - （任意・推奨）https://huggingface.co/ggml-org/whisper-vad/resolve/main/ggml-silero-v5.1.2.bin
2. ビルドに必要なもの：Vulkan SDK（`KhronosGroup.VulkanSDK`）、Visual Studio の C++ ツールと Windows SDK、venv 内の `cmake` `ninja` `setuptools` `wheel` `repairwheel` `setuptools-scm`
3. `pywhispercpp` のソースを submodule 込みで取得し、**`C:\pwc` のような短いパス**に置く（深い階層のサブビルドが Windows の MAX_PATH 260 文字を超えるため）。Git は `core.longpaths=true` で clone する。
4. `vcvars64.bat` を読み込んだ環境で、`GGML_VULKAN=1`、`CMAKE_GENERATOR=Ninja` を設定し、`pip install --no-build-isolation .` を実行する。
   - Ninja だと DLL が `bin\` に出力されるが、`setup.py` の wheel 修復処理は `bin\Release\` を探すので、失敗したら DLL を `bin\Release\` にコピーして再実行する。
5. ビルド後は Vulkan SDK と Windows SDK をアンインストールしても動く（実行時に必要なのはドライバー付属の `vulkan-1.dll` だけ）。

参考値（RX 7900 XTX）：17.7 秒の音声を約 0.2〜0.4 秒で文字起こし（CPU の `small` は 2.6 秒）。

### 既知の制限

- 自前の Vulkan ビルドは、複数の候補を同時に扱うデコード（ビームサーチ、`best_of>1` の温度フォールバック）で access violation を起こす。そのため `greedy={"best_of": 1}` に固定している。音楽や雑音の多い音声でだけフォールバックが走るので、きれいな読み上げ音声のテストでは再現しない。
- whisper.cpp のモデルはスレッドセーフでないため、文字起こしはロックで1件ずつ処理する。

## 精度の目安

Windows の読み上げ音声（3種類の声 × 話速 3 段階）で作った評価データで測定。会議アプリ相当の劣化（Opus 16kbps ＋ 雑音 SNR 15dB）を加えた条件を含む。

- 文字起こしの文字誤り率（CER）：約 2.5%
- 調整に使っていない言い換え文での質問判定（正しく表示 / 間違った質問を表示 / 質問でない発言に表示）：69.7% / 11.5% / 0%（調整前は 50.0% / 15.4% / 0%）

実際の動画（約 11 分半、BGM あり）を本番モードと同じ流れで処理し、手で直した正解と比べた結果：

| | 文字誤り率（CER） |
|---|---|
| 区間の切り出しを改善する前 | 55.2%（ほとんどが聞き取り漏れ） |
| 改善後 | 10.1% |
| 参考：区切らずに丸ごと文字起こし | 11.7% |

文字の一致で比べる方式なので、言い回しが大きく違う質問は当てにくい。その場合は、その言い方を `variants` に追加すると当たるようになる。
